# Доступ к поиску HH API

На первом этапе приложение только читает вакансии и оценивает их по локальному профилю. Отклики и доступ к личным резюме не подключены.

## Проверка 3 октября 2026

Один запрос GET https://api.hh.ru/vacancies?text=C%23&area=2&per_page=1 без токена вернул HTTP 403, errors[0].type=forbidden, request_id=17910434055771212544f64bff045001. Ответ не указывает конкретную причину; нельзя утверждать, что токен обязательно устранит ограничение. Повторять запросы для обхода ограничения не следует.

## Рекомендуемый путь

1. Открыть https://dev.hh.ru/admin и самостоятельно войти через HH.
2. Зарегистрировать приложение HH Job Agent. Описание: «Локальное персональное приложение для поиска вакансий и оценки соответствия моему профессиональному профилю. Текущий этап — чтение вакансий без отправки откликов». Указать собственный действующий контакт. Не выдумывать публичный сайт или адрес обратного вызова: если форма требует их, сначала уточнить требования HH.
3. Если кабинет предоставляет access_token приложения, сохранить его только локально в .env как HH_ACCESS_TOKEN. client_id и client_secret не являются access_token.
4. Перезапустить сервер через start.ps1 и выполнить один поиск. Наличие токена не гарантирует устранения общего forbidden.
5. Если сохраняется 403, обратиться в api@hh.ru с типом ошибки и request_id, описанием зарегистрированного приложения. Не включать пароль, токен или client_secret.

Текст для поддержки (отправляет владелец аккаунта):

«Здравствуйте! Разрабатываю локальное персональное приложение HH Job Agent для поиска вакансий по своему профилю. GET /vacancies без авторизации вернул 403 с errors.type=forbidden. Request ID: 17910434055771212544f64bff045001, дата 03.10.2026. Подскажите причину ограничения и необходимый официальный порядок доступа для чтения вакансий. На текущем этапе отклики не отправляются».

Для последующих откликов понадобится OAuth соискателя: владелец входит на стороне HH и разрешает доступ приложению. Пароль HH и пароль почты приложению передавать не нужно.
